What we built and why it matters

AOS is a full-featured e-commerce demo platform: accounts, catalogue, cart, checkout and orders. We treated it as a real enterprise product and ran a complete QA programme on it: reviews, manual testing, API, database, mobile and automation. The result is a traceable, CI-ready suite that proves release readiness in hours, not days.

✅ Project Assumptions

A1A stable AOS test environment is available across the 9 weeks — consistent test data and no surprise deployments during execution cycles.
A2Requirements and acceptance criteria are baselined after static review; later changes go through an agreed change-request process.
A3The team holds the needed access: test accounts, API credentials, database read access, and devices or emulators for mobile testing.

⚠️ Project Constraints

C1AOS is a public sandbox — occasional rendering glitches, slow responses and shared-data resets can cause false negatives that need manual re-verification.
C2A fixed 9-week window with part-time availability rules out exhaustive testing, so risk-based prioritisation targets the most business-critical flows.
C3No access to source code, server logs or monitoring means black-box analysis only — performance and security stay at sanity level.
